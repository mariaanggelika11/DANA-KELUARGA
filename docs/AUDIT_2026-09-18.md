# Audit Dana Keluarga — 18 September 2026

## Hasil dan batas pemeriksaan

Audit menggunakan source frontend/backend, schema Prisma, pengujian HTTP/service, browser lokal dengan API fixture, pembacaan database tanpa perubahan, dan halaman login publik `https://danakeluarga.bulmar.tech/` (HTTP 200). Tidak ada akun produksi yang dipakai untuk menjelajahi halaman terautentikasi. Perubahan belum di-deploy ke website publik. Lampiran berakhir pada bagian “27. DATE & CURRENCY — B”; pemeriksaan tetap mencakup format nominal/tanggal.

Perbaikan dilakukan bertahap pada implementasi yang ada, tanpa reset database, migration baru, seed akun, penghapusan transaksi, atau mengganti keseluruhan aplikasi. Perbaikan worker notifikasi dari tugas sebelumnya tetap dipertahankan.

## Alur registrasi final

Registrasi adalah **pemberian akses oleh administrator**, bukan pendaftaran publik. Tidak ada tautan undangan atau email otomatis dalam versi ini.

1. **Super Admin → Anggota → Tambah anggota → Buat keluarga baru**: isi satu identitas admin, email login, WhatsApp, password/konfirmasi, nama dan kode keluarga. Sistem membuat keluarga + akun + membership ADMIN + audit secara atomik. Setelah berhasil, keluarga tersebut dipilih pada daftar anggota. Langkah berikutnya adalah Setup Hirarki.
2. **Super Admin → Buat akun anggota**: pilih keluarga tujuan, isi identitas/email/WhatsApp/password/konfirmasi, tentukan ADMIN atau MEMBER. Akun dapat masuk memakai email tersebut. Tidak ada login otomatis karena operator masih menggunakan akun Super Admin.
3. **Super Admin → Hubungkan akun**: pilih keluarga, cari/pilih akun aktif, tentukan role. Password lama tetap berlaku. Akun Super Admin, akun inaktif, dan membership yang sudah ada ditolak.
4. **Admin keluarga → Tambah anggota**: membuat akun pada keluarga aktif saja. FamilyId yang dikirim klien tidak dapat digunakan untuk menyasar keluarga lain. Penghubungan akun lintas keluarga dilakukan Super Admin.

Admin berwenang menetapkan ADMIN/MEMBER pada keluarga sendiri sesuai perilaku aplikasi sebelumnya. Ini bukan dropdown role publik. Penetapan role keluarga tidak otomatis memberi approval; workflow tetap membutuhkan assignment Maker/Approver/Releaser. Role TREASURER lama dipertahankan, tidak ditawarkan untuk akun baru.

Email digunakan untuk masuk; “Nama lengkap” adalah identitas tampilan. Password awal disampaikan oleh administrator melalui jalur aman. UI tidak mengklaim telah mengirim email/WA. Reset password mandiri, undangan, dan kewajiban mengganti password pertama kali belum tersedia.

## Audit database baca-saja

Saat diperiksa: 5 akun, 2 keluarga, 5 membership, 1 pinjaman, 5 cicilan, 3 ledger, 0 approval policy/request, 0 FundGoal. Tidak ditemukan email NULL atau bentrok email case-insensitive pada data sekarang.

Satu pinjaman lama APPROVED mempunyai cicilan tetapi disbursedAt NULL. Data dipertahankan; penanganannya mengikuti [catatan rekonsiliasi](MIGRATION.md). Tidak menebak apakah uang pernah ditransfer. Belum ada policy keluarga asli, sehingga pengelola tetap perlu mengisi Setup Hirarki sebelum mengajukan pinjaman baru.

Tidak ada perubahan schema/migration pada audit ini. Field email database tetap nullable untuk kompatibilitas data lama; semua jalur API pembuatan akun baru mewajibkannya. Unique email/phone/family code/member relation dan transaksi database melindungi konflik pembuatan paralel. Normalisasi email dilakukan sebelum pengecekan/penyimpanan; query login tetap mendukung huruf besar pada akun legacy.

- Build TypeScript backend/frontend, validasi Prisma, lint frontend, serta `git diff --check`.

Script regresi browser disimpan pada `dana-keluarga-frontend/scripts/audit-ui.cjs`. Jalankan Vite pada localhost:5176, lalu jalankan script dengan `PLAYWRIGHT_MODULE` mengarah ke instalasi playwright-core dan `CHROME_PATH` bila executable Chrome berbeda. Script menolak hostname selain localhost/127.0.0.1 dan mengintersep API memakai fixture.

## Batasan yang tetap perlu pekerjaan terpisah

- WhatsApp dan pembayaran masih simulasi; SMTP/undangan/reset password/self-service profile belum tersedia.
- Token masih di localStorage sesuai arsitektur awal. Migrasi ke HttpOnly cookie memerlukan desain CSRF/CORS/deployment bersama; tidak diklaim sudah dilakukan. Tab browser berbeda belum memiliki koordinasi refresh lintas tab.
- Token refresh legacy masih memakai scan hash sampai berakhir; token baru memakai ID indexed. Logout mencabut refresh token; access token yang sudah diterbitkan tetap berlaku paling lama 15 menit.
- Konfigurasi reverse proxy/rate limiter IP harus diverifikasi saat deployment. Jangan mengaktifkan trust proxy sembarang tanpa mengetahui topologi.
- Daftar kas saat ini memuat 100 catatan terbaru; belum ada laporan/export atau pagination server untuk riwayat lengkap. Frontend utama masih besar meski registrasi dan komponen bersama sudah diekstrak; tidak dilakukan rewrite total.
- Ini bukan penyelesaian seluruh Business V2: tabungan per anggota, double-entry, target dana aktif, serta halaman audit umum tetap terpisah.


## Perbaikan P2021/P2022 dan pengosongan database

Atas permintaan eksplisit pengguna, seluruh tabel bisnis, anggota biasa, dan sesi login dikosongkan dalam transaction dengan backup privat terlebih dahulu. Satu akun SUPER_ADMIN aktif dipertahankan beserta credential aslinya. Riwayat `_prisma_migrations` dipertahankan sebagai metadata schema.

Migration `20260918120000_family_cash` yang sebelumnya tertunda berhasil diterapkan. Prisma Client dibuat ulang; build backend dan pembacaan seluruh 19 model berhasil. Hasil verifikasi: User=1; seluruh 18 model lain=0. Backup lokal berada di `.local-backups/before-requested-reset-1789723797381.json`, berizin 0600 dan diabaikan Git. Backup ini memuat data sensitif dan tidak boleh dipublikasikan.

Login ulang sebagai Super Admin setelah restart API. Akun anggota lama sudah dihapus; aplikasi mulai tanpa keluarga, pinjaman, transaksi, ataupun hirarki. Jangan menjalankan seed data contoh.


## Penghapusan WhatsApp dan penggunaan email saja

Permintaan terbaru menggantikan seluruh fitur WhatsApp dengan email. Migration `20260918170000_email_only` berhasil diterapkan setelah snapshot privat. Jumlah akun tetap 1, pinjaman 0, dan ledger 0; data bisnis tidak dihapus pada perubahan kanal ini. Worker, event deduplication, pembatalan pengingat, pengaturan, dan riwayat kini memakai EmailMessage. Riwayat inbox aplikasi tetap tersedia. Build backend/frontend, lint frontend, 125 test backend, dan integrasi kas PostgreSQL sementara lolos. SMTP belum dikonfigurasi sehingga pengiriman nyata belum aktif. Catatan WhatsApp pada bagian audit sebelumnya merupakan riwayat implementasi lama.


## Filter keluarga dan pencarian dropdown

Halaman Anggota Super Admin sekarang default ke Semua keluarga; parameter familyId opsional hanya untuk Super Admin. Identitas keluarga ditampilkan pada setiap keanggotaan. Backend tetap mengabaikan filter lintas keluarga dari pengguna biasa dan memakai keluarga aktif dari sesi.

SearchableSelect dipakai pada filter anggota, keluarga tujuan registrasi, Setup Hirarki, serta pergantian keluarga aktif. Pencarian memfilter nama/kode keluarga tanpa mengganti pilihan yang sudah ada. Dropdown native mempertahankan navigasi keyboard, dukungan mobile, dan validasi required.

Semua keluarga hanya digunakan sebagai filter daftar, bukan target penulisan atau konteks transaksi. Dropdown dengan pilihan sedikit, seperti peran anggota dan arah arus kas, tetap sederhana. Pencarian akun anggota existing sudah tersedia pada registrasi. Tidak diperlukan migration database. Build/lint frontend dan 37 test route backend lolos, termasuk empat pemeriksaan akses filter keluarga.

## Penyempurnaan tampilan pencarian keluarga

SearchableSelect diperbarui menjadi satu combobox dengan panel hasil, ikon pencarian/keluarga, tanda pilihan aktif, dan empty state. Input pencarian terpisah dan select native pada implementasi sebelumnya digantikan. Pilihan tidak berubah hanya karena mengetik pencarian. Navigasi ArrowUp/ArrowDown, Enter, Escape, klik di luar, dan validasi pemilihan keluarga wajib tetap didukung; Escape di dropdown tidak menutup dialog pendaftaran. Gaya terpusat di SearchableSelect.css dan digunakan seluruh pemilih keluarga.
